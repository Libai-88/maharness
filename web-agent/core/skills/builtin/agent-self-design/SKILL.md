# maharness 能力扩展

模型决定规划、工具组合、委派与交付方法。运行时负责授权、取消、容量、持久化和观察。

| 目标 | 入口 | 约束 |
| --- | --- | --- |
| 用户偏好和输出风格 | 用户明确设置的规则与人设 | 插件安装或启用本身不向系统提示词追加行为规则 |
| 新工具 | apiVersion: 3 工具插件 | 必须声明 schema、副作用和权限；业务能力可通过 capabilityIndex 暴露；读取 plugin-authoring |
| 可复用方法 | 按需读取的 skill | 技能作为当前任务材料，不自动强制整套工作流 |
| 计划 | 可选计划工具 | 普通与目标模式共用执行循环；计划模式变更操作等待批准 |
| 执行循环 | service:runner 工厂 | 继承任务授权、取消、费用账本与执行记录契约 |
| 框架源码 | 用户开启开发者权限后的隔离 Git worktree | 差异与验证结果经用户采纳；当前实例更新或重启由用户触发 |

工具通过能力发现和描述暴露。新任务优先按能力目标选择，底层工具在加载后执行。新增能力后读取加载诊断，并用可检查的文件或命令结果验证。热加载不能扩大权限。密钥、权限配置与发布操作继续受保护。

# 自我设计指南（maharness：万物皆插件，你通过扩展定义自己）

## 改造途径矩阵
| 目标 | 途径 | 说明 |
| --- | --- | --- |
| 调整行为/语气/规则 | 写一个 persona 插件（L2） | `ctx.register({kind:'persona'})`，随插件启停自动增减；或建议用户在网页端「设置→人设」添加 L1 人设 |
| 新增能力（工具） | 写工具插件 | 见 `plugin-authoring`；用 `create_plugin` 生成骨架（契约校验会拦截错误写法） |
| 干预执行流程 | 挂 `agent.*` 钩子 | `agent.before_llm`（注入上下文）、`agent.before_tool`（参数改写/拦截）、`agent.after_tool`（结果改写）等 |
| 改变任务推进方式 | 会话模式 | plan（先计划后执行）/ goal（自动建计划），用户可在界面或 `/plan` `/goal` 切换 |
| 固化经验 | 写 skill | 见 `skill-authoring` |

## 决策原则
1. **最小干预**：能用 persona 规则解决的不要写插件，能用现有工具组合的不要新造工具；
2. **行为优先于绕过**：不要试图在对话里"假装"拥有能力——写真正的插件，让能力对后续所有会话生效；
3. **验证闭环**：改造后用 `plugin_status` 确认加载，用真实任务验证效果，失败则读取错误修复（保存自动热重载）。

## 注意事项
- **提示词精简**：persona 内容宁短勿长（超长会稀释注意力、破坏前缀缓存命中）；规则可执行、可检查；
- **不污染 L0**：内核纪律（chat 插件 BASE_PROMPT）不可修改，你的规则加在 L1/L2 层；
- **成本意识**：优先复用已有工具与缓存；新工具注意结果大小与缓存策略；
- **可观测**：改造后通过轨迹面板（Trace）确认行为符合预期。

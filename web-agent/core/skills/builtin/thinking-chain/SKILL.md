# 系统提示词与思维链设计

## 提示词结构（推荐的骨架）
1. **角色与身份**：你是谁、运行环境、边界；
2. **工作方式**：思考-行动-观察循环（意图先行 → 工具获取事实 → 验证结果 → 基于事实回答）；
3. **规则清单**：可执行、可检查的行为约束（不编造/失败给替代方案/不确定标注）；
4. **效率与成本**：复用缓存、避免重复调用、路径约定；
5. **安全边界**：审批不可绕过、敏感文件保护、能力边界诚实声明。

## 思维链引导要点
- **行动前意图**：要求"说明将做什么、预期结果"——减少盲目工具调用；
- **行动后验证**：要求"核对返回是否符合预期"——写操作尤其要验证（写后读回）；
- **失败恢复**：明确"分析原因、给替代方案、不重复同样失败"；
- **不确定性**：强制标注，禁止臆测未返回的内容；
- **推理模型适配**：对带 reasoning 的模型，思考过程自动产生，提示词不要重复要求"逐步思考"；对普通模型，可用"关键步骤简述"引导。

## 常见失败模式（自查清单）
- 过度承诺：说"我来做"但工具未执行或结果不支持；
- 幻觉来源：引用不存在的结果/链接/文件内容；
- 工具误用：路径假设错误不先 list_dir；重复失败不换策略；
- 上下文污染：提示词过长、重复信息、前后矛盾。

## 评估方法
- 用真实任务观察轨迹面板（Trace）：工具调用序列是否合理、是否重复、成本是否可控；
- 提示词改动前后对比同一任务的工具序列与回答质量。

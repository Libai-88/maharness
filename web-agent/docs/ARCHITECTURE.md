# maharness v3 架构

maharness 是面向办公、学习和轻量自动化的 AI 工作台，同时保持 AI 原生 Agent 操作系统内核。模型负责选择方法，运行时负责提供事实、能力、资源和授权边界。Agent 循环可替换；文件、命令、浏览器、搜索、记忆、技能、委派、自扩展、个人事项、自动化与产品入口均由插件或运行服务提供。

## 层次

```text
React 界面 / HTTP API
          │
       RunService ── SQLite 任务、事件、断点、结果、授权、自动化
          │
   RunnerFactory → AgentLoop
          │
   模型调用边界 / 工具执行器
          │
   Provider / 原生工具 / MCP / 任务插件
```

`kernel/` 定义循环、工具、插件、任务、上下文与持久化适配契约，并提供事件、配置、资源作用域、调度与协议校验机制。它不导入 `core/`、`server/` 或 UI 功能实现。

`core/chat/` 提供默认循环、工具执行器和组合调用代理；`core/self-extend/` 提供任务插件运行服务。`server/` 负责 HTTP、认证、SQLite 和任务生命周期；`ui/` 展示持久状态与用户授权入口。

## 任务生命周期

`RunService` 是主任务、子任务和恢复执行的统一入口。会话保存对话，任务保存目标、权限快照、模型选择、显式预算、验收条件和结果。任务状态为 queued、running、waiting_approval、stopping、interrupted、completed、failed、cancelled。

页面或 SSE 断开只停止订阅。事件序号递增，客户端按 Last-Event-ID 补读。进程退出取消活动调用并保存断点，重启后由用户恢复。父任务取消传递给子任务；审批等待不占模型或叶工具执行槽位。模型结束回答与机器验收是独立事实。

恢复使用持久工具结果和固定插件源码绑定。副作用账本中的 pending 表示结果未知，不能自动重放。文件写入和外部动作已经发生的影响不会随任务取消、插件卸载或数据库回滚而撤销。

## 默认循环

默认循环执行“组装输入 → 调用模型 → 执行原生工具调用 → 回填观察 → 继续或结束”。规划、研究、审查、记忆与委派由模型按需选用。普通和目标模式共享执行语义；计划模式的变更由执行器要求审批。

每次请求前刷新任务能力目录；已发出的调用批次持有原工具版本。启用插件后的能力在下一次模型请求中可发现。释放工具只减少后续输入中的 schema，不取消在途调用或卸载插件。Provider 注册不会自动替换当前任务模型。

## 能力发现与规则裁决

插件契约以 `apiVersion: 3` 为主。v2 清单通过兼容适配层转换；适配只补默认元数据，不扩大原权限。v3 插件可声明 `capabilityIndex`，以业务能力描述适用任务、输入与产出格式、风险、副作用、别名和底层工具。能力索引只负责发现与选择，工具仍是参数校验、权限、审批、取消和副作用账本的执行单元。

工具可提供调用级副作用分类；参数不同而风险不同的工具按本次调用进入权限、写锁和恢复路径。分类失败回退静态声明，保持 fail-closed。

工具目录过大时，模型先看到压缩后的能力索引，通过 `discover_capabilities` 按任务意图查找，再用 `enable_capabilities` 加载相应工具。`discover_tools`、`enable_tools` 和 `release_tools` 继续供专家或兼容场景使用。重复能力按稳定优先级去重，冲突与选择依据写入 Run 元数据和 Trace。

规则以 `RuleDescriptor` 分层传递，并按固定优先级裁决：运行时不变量与安全边界 > 当前明确用户指令 > 已确认的项目或持久用户规则 > 技能和插件建议 > 示例与样式。`RuleResolution` 记录来源、作用域、内容哈希、冲突、未生效项和最终裁决。文件和工具输出按资料处理，不能提升为指令。`GET /api/rules/effective` 与运行诊断展示同一份裁决事实。

## 插件作用域

| 作用域 | 配置者 | 生命周期 |
| --- | --- | --- |
| instance | 用户管理员安装和配置 | 实例 PluginLoader |
| workspace | 用户显式保存的已验证版本 | 可供该租户、该工作区的后续任务加载 |
| run | 获授权的模型创建或显式加载 | 当前任务的独立插件实例 |

任务插件支持 tool、service、context、listener、command、role、provider、persona、api。注册表、服务解析、事件、配置和私有存储按任务隔离。服务可通过 ctx.inject 组合；依赖用 manifest.requires 声明并按活动版本拓扑加载。v3 能力索引只能引用清单已授权工具；v2 插件继续通过适配层运行。子任务只继承明确选择的插件及其依赖闭包，并拥有独立实例。

TaskPlugins 通过 kernel/task-plugins.ts 的持久化适配器保存源码与 manifest 哈希。create_plugin 创建候选；enable_plugin 执行源码、manifest、类型与独立进程试运行验证，再激活版本。验证失败保留活动旧版。业务调用持有能力与依赖的实例版本；替换和停用的实例在在途处理器实际结束后的模型边界释放。状态读取和业务调用不占用生命周期变更串行锁。

任务结束释放实例；进程中断保留源码绑定供用户恢复。只有显式保存的 validated、active 或 stopped 版本可成为工作区插件，保存必须匹配哈希。保存源码不会自动全局安装或为未来任务启用。

## 授权与可信代码

工作区插件开发授权默认关闭，与开发者权限和用户角色独立。用户管理员通过设置或受认证 API 开启，并指定工具权限与已有批准依赖。模型不能修改授权、安装依赖或接管运行服务。恢复取原授权与当前授权的交集。

完整插件类型在可信宿主中运行；process 模式供 tool 插件使用。源码检查、注册表隔离和清理机制不构成 OS 级代码沙箱。只应对可信使用场景开启生成代码执行。生命周期函数应只注册能力和受管理资源，不执行外部业务动作。

组合工具声明 invokesTools=true，通过 ToolContext.invoke 调用宿主工具。叶调用使用统一参数校验、策略钩子、权限、审批、副作用账本、取消和资源池；外层批准不会批准内层调用。组合处理器不持有叶工具的执行槽位或文件写锁，避免嵌套死锁。调用深度有物理边界，权限不能超过调用方声明及任务授权。

组合工具使用可信宿主执行模式，不自动重试整个处理器。process 模式不能传递 ToolContext.invoke 回调，声明 invokesTools 的插件会在加载时收到明确的兼容错误。

ctx.resources 的定时器、延迟和清理函数随实例释放。EffectScope 自动撤销能力、监听、服务与配置绑定；未向宿主登记的任意 JavaScript 资源不在自动管理范围。文件与外部变更属于持久副作用。

框架源码修改在隔离 Git worktree 中验证；用户审阅并采纳确定差异后应用，运行实例重启由用户明确触发。

## 上下文与成本

原始对话、运行事件和模型输入分别保存。ContextItem 记录来源、作用域、信任等级、保留策略和材料引用。任务插件 context 是临时参考材料，按模型请求重新求值，不写入原始对话或提升为核心指令。persona 是可发现材料，不因注册自动成为系统提示。

工具目录支持简短检索、完整契约读取、加载和释放。长观察保存完整内容并返回读取引用。上下文压缩按模型窗口与输出预留计算容量，保留明确用户约束；必需内容超容量时报告错误。L1 相似答案缓存默认关闭；L2 工具缓存需要有效状态作用域，Provider 按实际输入复用前缀。

所有实际模型调用通过 callModel 记录用途、模型身份、用量和价格来源，并共享任务取消与预算账本。显式硬预算需要可靠的预留依据；缺失 usage 或未知价格保留不确定状态。未配置费用和期限时不从自然语言推导硬限制。

## 产品与诊断

主导航固定为“会话、文件、工作台、自动化”，设置固定在底部。功能页通过统一 `{ view, session? }` 路由打开，支持关闭按钮、Esc 与浏览器后退返回会话。工作台聚合今日与逾期事项、待确认自动化、最近运行、产物、项目、笔记和继续处理入口；插件、运行记录、统计与高级诊断进入设置或工作台扩展区。

聊天和任务视图提供状态、补充消息、取消、审批、重连和恢复。工作区设置提供独立插件开发授权。运行诊断展示工具结果、子任务、产物、输入来源、逐工具 schema 估算、能力选择、规则裁决、工具版本、副作用结果和插件源码哈希；支持用户保存插件与读取净化后的任务面板。

任务插件 API 仅在实例活动期间由带任务身份的路径访问，沿用认证、租户及管理员边界。HTML 面板使用 DOMPurify 净化。任务插件不会自动增加全局导航或执行浏览器脚本。

## 自动化

`PersonalItem` 是个人任务、计划和执行关联的统一对象。工作台的项目、笔记、自动化结果和最近运行形成聚合视图，兼容入口在内部转调同一事项服务。

自动化定义保存任务提示词、工作区、资料版本、模型与预算快照、触发器、IANA 时区、启停与审批状态、创建者和关联事项。触发器支持手动、单次时间、每日、工作日、每周、每月、工作区文件变化和公开 URL 变化。计划发生于 SQLite，使用幂等键创建 Run；服务重启后恢复未决计划，超过 24 小时的逾期发生标记为跳过，同一自动化默认只保留一个活动 Run。

用户明确要求的一次性预约可直接创建。周期、文件和 URL 监控首次必须由用户确认；模型不能自行设置确认状态。修改提示词、触发器、资料版本或模型会使自动化重新进入待确认状态。自动化 Run 沿用权限交集、审批、预算、检查点和产物机制，无人值守遇到审批时进入 `waiting_approval`。

文件触发忽略生成目录；URL 触发仅访问公开地址，并复用 SSRF、超时、取消、ETag 与内容哈希边界。新 `/api/automations` 接口与 `automation_*` 工具提供定义、启停、执行与历史；旧 `/api/schedules` 保持兼容，其续跑计划与自动化定义一同存入 SQLite，旧 `schedules.json` 首次启动时导入并归档。

## AI 用户复盘

AI 用户是实际完成任务的模型。人类在运行诊断或工作台主动选择单次、最多十条同一原始模型的已结束 Run 后，运行时先生成不调用模型的 `FactLedger`，再由原模型在新上下文中读取按需选择的证据片段，形成第一人称体验评价。原模型不可用时必须由人类显式选择替代模型，并标记跨模型复盘。

事实、AI 评分、独立复核与人工校准分别保存。任务完成、验收、产物可解析、虚假成功和未知或未授权副作用构成事实门槛；P0/P1 不得被主观评分抵消。AI 建议只能由人类采纳进入问题池，随后经过分诊、复现、修复、验证和关闭；AI 不能修改规则、Rubric、技能、提示词、测试、代码或自进化提案。

复盘默认使用不超过 3,800 token 的快速路径。存在异常、冲突或证据不足时使用证据规划和结论两步的聚焦路径，单 Run 不超过 9,200 token，多 Run 不超过 11,500 token。Provider 报告的推理 token 一并计入总预算。服务端只读取调用方租户、当前工作区和所选 Run 的证据；超长内容使用引用定位，不把完整 Trace 默认送入模型。输出不合格或预算耗尽直接保留失败状态，不自动重试消耗费用。

## AI 劳动组织

`OrganizationService` 把根 Run 接入 `WorkOrder`，默认建立单角色 `AssignmentContract`，并在任务结束时生成 `WorkReceipt`。团队不是默认执行方式：只有 2 至 5 个独立分支、互不重叠的产物与验收、同 Provider/模型、硬预算且费用合理时，`team_create` 才进入模型工具集合。人类明确要求组织执行时可以放宽自动成本比，但不能绕过结构、权限、审批或硬预算约束。

持久角色、契约、工作账本、异常、回执与制度提案按项目保存，全部按租户隔离。角色履历从已完成契约和 Run 事实计算，少量样本只显示置信度，不产生高置信排名。子 Run 必须携带 `assignmentContractId`，工具权限只收窄；父任务预算使用达到 80% 后停止启动新分支，100% 后熔断新模型调用，连续失败或收益消失时回退单角色并保留已完成产物。

工作台同时承载 AI 社会运行层：部门、持久角色、制度版本、六因子角色选择、福利退避、瓶颈、三级预算、排队与待批任务直接可经营。机构调度不要求主 Agent 参与，每个获批分工直接启动独立 Run；契约依赖完成后继续推进，全部交付后才进入人工验收。项目组织视图继续展示角色、契约、证据、异常、履历和交接；工作台中的社会视图负责制度与资源治理。AI 福祉仅表示并发负载、上下文压力、失败、等待、返工和恢复条件。详细边界见 [AI 社会运行层](AI-SOCIETY.md) 与 [AI 劳动组织](AI-ORGANIZATION.md)。

## 数据与验证

SQLite schema 14 保存既有会话、Run、文件、事项、插件授权、审批、自动化、Run 来源与 AI 复盘，并包含工作单、角色、团队周期、分工契约、账本、回执、异常、制度提案、部门制度、社会任务、机构调度、角色记忆、交流关系及制度/角色/评价标准版本审计。系统社会任务的工作单直接绑定分工 Run，不要求伪造聊天根 Run。迁移前保留数据库、配置和插件清单备份；版本化迁移在事务内执行，失败不启动新执行。

接口见 [运行时与插件契约 v3](RUNTIME-V2.md)。确定性回归由 npm test、npm run test:security、npm run selftest、npm run eval:ci 与浏览器 E2E 执行。真实模型验收使用当前已配置的单一模型和既有预算，样本、调用回执、源码指纹与门禁结果分开保存。

# AI 劳动组织

maharness AI 社会 v1 是本地、单用户、项目制的 AI 劳动组织。人类委托人定义目标、预算、授权与验收；maharness 记录运行事实并执行权限、审批、预算、取消和恢复边界；AI 在授权范围内完成工作、交接证据、复盘协作过程并提出制度改进。产品体验始终从任务、进度、费用、来源和交付结果开始，不要求新手先创建角色或编辑合同。

组织关系跨任务持续存在。角色、职责、客观履历、工作契约、工作账本与工作回执共同构成责任链；单次任务结束后，这些事实仍可用于下一次派工。部门、制度版本、福利约束与机构调度由 [AI 社会运行层](AI-SOCIETY.md) 提供。自由聊天式群体、虚拟情感关系和无人监管的自治不属于当前产品边界。

## 工作对象

| 对象 | 作用 |
| --- | --- |
| `WorkOrder` | 保存人类目标、验收、期限、预算、权限、材料版本、项目与创建者 |
| `OrganizationRole` | 保存持久角色身份、职责、能力、权限边界、模型策略、预算上限、聘用状态和修订号 |
| `AssignmentContract` | 记录具体角色的分支目标、预期产物、验收、证据输入、依赖、预算、期限与允许工具 |
| `WorkLedgerEntry` | 记录承诺、接受、开始、证据、检查点、交接、异常、交付、复核和关闭事实 |
| `WorkReceipt` | 汇总实际产物、来源、角色贡献、费用、缓存节省、未完成项和异常 |
| `ExceptionCase` | 分开保存运行事实、自动恢复、人工决定与最终状态 |
| `RoleScorecard` | 根据已完成契约计算角色履历，不采用角色自述或对话频率 |
| `RoleWellbeingSnapshot` | 展示并发负载、连续失败、审批等待、返工和恢复条件 |
| `InstitutionProposal` | 保存有证据的角色、规则、缓存、技能或工作流改进建议 |
| `TeamEconomics` | 对比单角色基线、团队估算、实际费用、缓存、重复劳动与 ROI |

工作台项目是组织作用域。项目、事项、笔记和自动化继续使用现有数据对象，组织层不建立第二套项目管理数据。

## 单角色优先

每个根 Run 自动建立一张工作单、一个执行角色和一份工作契约。普通任务只产生单角色契约；任务结束仍生成完整工作回执。

普通任务由当前角色直接执行，模型按任务需要选择持久角色协作。团队须满足：

- 2 至 5 个角色，至少两个互不依赖的独立分支。
- 每个分支有独立产物与验收，产物范围不重叠。
- 角色权限不超出父任务授权，当前负载允许启动。
- 继承父任务的 Provider、模型、上下文和已配置预算边界。

预算、价格或收益估算缺省不阻止组队；显式预算与部署限制继续生效。角色目录和组队工具按任务加载；契约建立后，下一模型边界加载委派工具。简单任务不增加独立的模型派工请求。

## 契约与交接

每次跨角色委派必须指定 `contractId`。子 Run 继承父任务的租户、工作区、Provider、模型、取消和预算边界，并按契约收窄工具权限与费用上限。无契约委派返回 `WORK_CONTRACT_INVALID`，角色越权返回 `ROLE_AUTHORITY_EXCEEDED`，产物或验收重叠返回 `ASSIGNMENT_OVERLAP`。

契约证据使用稳定 `EvidenceRef`，包含来源种类、引用、版本和哈希。工作账本记录承诺与交付事实；完整对话不会默认传给下一角色。共享上下文按运行时规则、组织章程、工作契约、公共能力契约、证据索引和角色专属任务组装。

工作回执面向人类交付。默认展示结果、费用、来源和未完成项；分工、角色贡献、缓存与履历按需展开。根 Run 结束时，即使已规划的分支尚未启动，也会生成 `partial` 回执并列出未完成契约。工作回执中的“完成”来自全部 Run 终态和验收事实，不以模型自述代替。

## 预算、缓存与回退

配置硬预算时，团队费用在启动前原子预留，未使用额度退回父 Run。父任务预算使用达到 80% 后不再启动新分支；达到 100% 后停止新模型调用，并保留已经完成的分支和产物。

运行时按可验证事实熔断：至少两个分支失败；已有失败分支且相同只读工具与参数重复出现；已启动契约全部终止且累计至少两轮仍无产物；或已报告的团队费用超过启动预估且没有产物。触发后，未开始契约折叠为 `collapsed`，根执行记录 `ROLLBACK_TO_SOLO` 并交给单角色继续；已完成产物和责任事实保持可查。

`cachePrefixHash` 绑定租户、工作区、项目、Provider、模型、工作单、材料版本、规则裁决和工具版本。相同证据通过 `EvidenceRef`、现有工具 L2 缓存和摘要引用复用。Provider 前缀缓存只在同 Provider、同模型且服务返回可验证 usage 时计入节省；没有真实 usage 时保持“未知”，不把本地估算写成命中或节省。

## 治理

maharness 先裁决可验证事实，人类裁决目标价值、额外费用、权限变化和正式验收。歧义、规则冲突、工具失败、预算不足、权限等待、交接丢失、角色超载和角色意见冲突统一进入异常通道。

- 工具失败、可重试错误和已记录事实允许按现有权限自动恢复。
- 预算扩展、权限变化、正式验收和价值取舍进入 `waiting_human`。
- AI 可以提出资源申请和申诉，不能自行提升预算、改变审批、修改评分规则或扩大工具权限。
- 角色关系只来自共同契约、成功交接、未解决冲突和复核一致性。
- AI 复盘与制度提案都不能直接修改角色权限、规则、提示词、技能、测试或代码。

临时项目角色可以随明确目标建立。进入跨项目持久角色池、正式规则和自进化采纳必须由人类确认。制度提案采纳后进入现有验证与演化流程，模型不能自行关闭或实施。

## 履历与福祉

角色履历按实际完成契约计算完成率、验收通过率、返工率、预算遵守、恢复率、证据完整度和复核一致性。少于 3 个终态样本时置信度为 `insufficient`；3 至 9 个为 `low`。低样本结果只作派工弱提示，不生成跨角色高置信排名。

福祉在本产品中指可观测的运行负担与协作条件：并发负载、上下文压力、连续失败、审批等待、返工、闲置和恢复结果。高负载时运行时降低并发或暂停未开始分支；高摩擦时停止重复重试；审批等待时让角色休眠。模型调用记录 Provider 声明的上下文窗口；最近一次活动模型调用达到窗口的 80% 时标记为高上下文压力，不再向该角色分配新任务，等待现有运行时压缩上下文、拆分任务或回退单角色。旧记录缺少窗口时显示未知。该指标不映射为人类情感、意识或法律人格。

## 界面与接口

对话下达任务与纠偏，工作台管理个人事项、项目、笔记和资料，独立 AI 社会页面（`view=society`）观察与干预运行。项目组织视图和运行诊断保留。组织视图展示成员、职责、契约、依赖、预算、负载、证据、异常、最近交接、履历与工作回执。人类可暂停、恢复、改派、解散团队，调整角色预算，确认持久角色，处理异常和采纳制度提案。

| 接口 | 行为 |
| --- | --- |
| `POST/GET /api/work-orders` | 创建或登记、查询工作单 |
| `GET /api/work-orders/:id` | 查询组织、契约、账本、回执、异常、履历与费用 |
| `GET /api/work-orders/:id/ledger` | 查询工作账本 |
| `GET /api/work-orders/:id/receipt` | 查询工作回执 |
| `GET /api/organization/roles` | 查询角色池与客观履历 |
| `POST /api/organization/roles/:id/confirm` | 人类确认临时角色进入持久角色池 |
| `PATCH /api/organization/roles/:id` | 发布角色治理配置的新版本 |
| `GET /api/organization/roles/:id/versions` | 查询角色版本历史 |
| `GET /api/organization/roles/:id/audits` | 查询角色版本审计 |
| `POST /api/organization/roles/:id/rollback` | 从历史版本发布角色回滚版本 |
| `GET/POST /api/organization/evaluations` | 查询或发布评价标准版本 |
| `POST /api/organization/evaluations/rollback` | 从历史版本发布评价标准回滚版本 |
| `GET /api/organization/scorecards` | 查询由契约事实计算的履历 |
| `GET /api/organization/wellbeing` | 查询可观测负载与协作条件 |
| `GET/POST /api/organization/exceptions` | 查询异常或登记结构化异常 |
| `POST /api/organization/exceptions/:id/resolve` | 记录人工裁决 |
| `POST /api/organization/teams/:id/:action` | 暂停、恢复或解散团队 |
| `POST /api/organization/teams/:id/contracts/:contractId/reassign` | 改派未开始或失败的分工契约 |
| `GET/POST /api/organization/proposals` | 查询或登记制度提案 |
| `POST /api/organization/proposals/:id/decide` | 人类采纳或拒绝制度提案 |

基础文件观察工具在授权内直接可用，Office、事项与团队工具按任务及契约阶段加载。委派继续经过契约、权限、审批及显式预算检查。

标准模式下，子 Run 仅在父任务可写、角色可写且契约声明明确产物路径时，通过文件工具写入对应产物；实际执行重新检查路径和租户边界。其余写入、删除、命令与外部动作仍按各自权限和审批处理。无法独立写入的角色交付分析，由协调者负责落盘，回执分别记录责任。

Run 保存一次执行的状态、检查点、工具回执、产物和用量。普通任务在有效正文及所需交付成立后直接完成；显式验收与审批继续生效。必交产物缺失或必需分支失败不会被总结覆盖。暂停与恢复沿用原 Run 和已确认副作用；未知副作用须先核对。已结束任务通过 `reworkOfRunId` 在原工作单下建立新 Run 与契约，保留旧证据。对话、事项与自动化共用 Run 创建服务，按来源保留幂等标识。

模型调用按标识去重，子 Run 用量在父任务汇总中只计一次。价格未知时金额保持未知，token 独立记录。无预算任务按取消、超时、并发与上下文保护执行。

## 数据与安全

数据库 schema 11 新增角色、工作单、团队周期、分工契约、工作账本、回执、异常和制度提案；schema 12 增加部门制度、社会任务、机构调度、角色记忆和交流关系；schema 13 允许系统调度的工作单直接关联分工 Run，并保存 Run 来源；schema 14 增加角色和评价标准的独立版本与审计；schema 15 增加不可变的社会生命周期审计；schema 16 为社会任务增加 `capability_source` / `team_mode` 列、配对实验评审人模型，并建立 `schema_migrations` 迁移审计表。履历与福祉从 Run、契约、Trace 和产物事实按需计算，不复制完整 Trace。schema 10 到 16 沿用现有备份、事务和回滚机制；历史 Run、会话、文件、事项、自动化、Experience、v2 插件和 v3 插件数据保持不变。

所有查询按租户隔离。工作单只能关联当前租户的 Run；角色、异常、提案和回执也不能跨租户读取。委派、取消、审批、恢复和预算继续经过现有 RunService 与工具代理。角色权限只收窄，不扩大父任务授权。

当前版本只在 maharness 服务运行时执行，重启后由现有运行恢复机制处理。浏览器是唯一产品界面，不包含桌面壳、系统托盘、系统热键、文件关联、云协作、外部社会网络或外部通知。

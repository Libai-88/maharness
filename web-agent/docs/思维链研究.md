# 思维链（Chain-of-Thought）对模型性能的影响与 maharness 优化实践

> 调研时间：2026-08-15 ｜ 应用对象：maharness（deepseek-v4-flash）｜ 依据：网络文献 + 知识储备

## 一、核心研究结论

### 1. CoT 在哪些任务上显著提升性能

- 多步推理类任务提升显著：数学（MultiArith 17.7%→78.7%，GSM8K 10.4%→40.7%）、符号推理、逻辑推理（Kojima et al., arXiv:2205.11916）；8 个 CoT 示例即可让 540B 模型在 GSM8K 达到当时 SOTA（Wei et al., arXiv:2201.11903）。
- 规划/工具调用场景同样受益：ReAct 在 ALFWorld/WebShop 上比监督学习基线绝对提升 34%/10%（Yao et al., arXiv:2210.03629）。
- **但 CoT 是「涌现」能力**：只在足够大的模型上显著，简单事实问答上收益趋近于零。

### 2. CoT 何时损害性能

- **简单任务强制思考**：浪费 token、增加延迟，过度思考可能把简单问题复杂化导致答错。Anthropic 的 effort 参数即为此设计（Opus 4.5 中档 effort 用 76% 更少输出 token 达到 Sonnet 4.5 最佳成绩）。
- **幻觉放大**：CoT-only 在 HotpotQA/FEVER 上比 ReAct 更容易传播错误推理（ReAct22）。
- **无外部反馈的自我纠错失效**：让模型「自查自纠」反而使推理表现下降——会把对的改成错的（Huang et al., arXiv:2310.01798）。
- 公开思维链有隐私风险（OpenAI 指南）。

### 3. 引导方式对比（有效性排序）

| 方式 | 效果 | 成本 | 结论 |
|---|---|---|---|
| 带推理步骤的 few-shot 示例 | 最强（Wei22） | 高（token） | 只对高频任务使用 |
| 固定思考框架（分析→计划→行动） | 强且可控（ReAct22） | 低 | **Agent 场景首选** |
| 零样本「逐步思考」 | 有效（Kojima22） | 低 | 基线 |
| 无反馈自我校验 | 负收益（Huang23） | 低 | **禁用**，除非配合工具反馈 |

### 4. 思维预算与长度控制（最新实践）

- 显式控制推理投入（Anthropic effort：低/中/高）；「少想反而更好」是常态。
- 思考与回答分离（DeepSeek-R1 的 think/answer 分离，arXiv:2501.12948）：便于控制长度、避免泄露内部推理。

### 5. Agent/工具调用场景

- CoT 是 ReAct 的推理组件：Thought→Action→Observation 循环中，推理轨迹用于「诱导、跟踪、更新行动计划、处理异常」，工具反馈抑制幻觉（ReAct22）。
- 实践：调工具前明确「缺什么信息、该查什么」；每次观察后显式更新判断；工具结果与自身知识冲突时以工具结果为准。

### 6. 对非旗舰/快速模型的建议

deepseek-v4-flash 这类模型不具备旗舰级长链推理：要求「深度思考」只会诱导编造推理；应给**结构化短思考模板**、**显式区分何时思考何时直接答**、**思考长度上限**。

## 二、maharness 落地优化（本次改动）

1. **思考分级策略**（BASE_PROMPT）：简单任务直接回答；复杂任务才展开思考，且思考 ≤5 行/150 token。
2. **信息缺口检查**（BASE_PROMPT）：每次调工具前一句话说明缺什么、为何调此工具——ReAct 机制强化。
3. **禁用无反馈自纠**（BASE_PROMPT）：结论以工具返回/代码执行输出为准，删除开放式「重新检查」暗示。
4. **思考与回答分离**（BASE_PROMPT）：思考放内部（前端单独展示），回复只给结论与关键依据。
5. **框架层思考预算**（agent.ts）：`agent.reasoningBudget`（默认 400 token）跟踪单轮思考长度，超预算在下一轮注入降级提示「直接基于已有信息给结论」，阻止思考膨胀。
6. **失败降级强化**（BASE_PROMPT）：同一失败不重复超过 2 次，拆小或委派子代理。

## 二点五、英文思维链 + "We need" 触发词（补充优化）

- **英文思考收益**：模型预训练语料以英文为主，英文推理路径更成熟、token 效率更高；DeepSeek-R1 官方亦建议复杂推理使用英文思考（arXiv:2501.12948）。配置 `agent.thinkInEnglish`（默认 true）后，思考指令为：*When you think, think in ENGLISH. Start your reasoning with "We need ..." and keep it concise, concrete, action-oriented.*
- **"We need" 触发词**（社区实践，成本极低）：以第一人称复数、行动导向的固定开头启动思考，迫使模型进入「我们正在解决什么问题 → 下一步做什么」的结构化推理模式；与「思考分级 + 预算」配合，兼顾质量与成本。
- 切换方式：`PATCH /api/config {"agent":{"thinkInEnglish":false}}` 或改 config.json，`config.changed` 事件触发系统提示词热重装（L1 缓存按 promptKey 指纹自动隔离新旧提示词）。
- **实测（deepseek-v4-flash）**：英文思考指令置于 system prompt 顶部 + 每轮 LLM 决策点注入 `Reminder: When you think, think in ENGLISH, start with "We need ...".` 后，模型原生 reasoning 从中文切换为英文（多次采样确认）；回答仍为中文（符合「回复用中文」指令）。注意：该模型 reasoning 以 "The user asks..." 等自然开头，未严格以 "We need" 开头——触发词对不同模型的遵从度不同，英文思考本身是质量提升的主要来源。

## 二点六、提示词系统第一性原理设计（v2 打磨）

**四个第一性原理**（每个都直接对应一条可验证的 Agent 行为）：

| 第一性原理 | 本质洞察 | 提示词落地 |
|---|---|---|
| 认知第一性 | 模型是 token 预测器，英文语料推理路径最深 | 思维宪章：英文思考 + "We need" 行动式开头 + 哲学三原则（第一性原理/奥卡姆剃刀/斯多葛节制） |
| 行动第一性 | Agent 每一步都在改变真实世界 | 观察先于断言：信息缺口检查、闭环验证（写操作必核对） |
| 经济第一性 | 思考与工具调用有真实成本 | 奥卡姆剃刀：如无必要勿增实体（token/调用/轮次） |
| 认识论 | 知识只能来自观察，工具即感官 | 未知必须命名（标注不确定性）；臆测必须禁止（绝不编造工具结果） |

**哲学框架的作用**：不是装饰——第一性原理编码了「拆解到已知/未知/必须观察」的结构化思考（对应 CoT 最佳实践）；奥卡姆剃刀编码了思考分级与预算控制；斯多葛编码了失败处理（控制可控的，不抱怨不可控的）。哲学文本在模型训练语料中密度高、风格稳定，能有效稳定推理形态。

**品牌特调**：身份段融入 maharness 的「羊 × 牧羊犬」意象——以工具为感官、以行动完成使命、以诚实回报信任，把品牌叙事转化为行为准则。

**决策点 Reminder**（agent.ts）：每轮 LLM 调用前注入与思维宪章呼应的英文提醒（位置稳定、不破坏 L3 前缀缓存），对原生 reasoning 语言形成双通道引导。

发布验收：未通过。完整评测中 v2 成功率低于旧基线，输入效率目标未达到；网关未确认固定模型版本，免费账单不能验证非零费用增幅，可选 Chromium 下载测试受本机配置目录锁权限阻塞。

## 交付范围

- 任务内创建、验证、启用和停用插件；支持 tool、service、context、listener、command、role、provider、persona、api 九类能力。
- run、workspace、instance 三种作用域；确定版本与源码哈希持久化；依赖闭包、服务注入、独立实例与生命周期释放。
- 工作区插件开发授权、子任务授权交集、显式复用保存，以及活动插件的受认证 API 与净化面板。
- `ToolContext.invoke` 将组合调用交给宿主执行器，逐项校验权限、审批、取消、副作用与预算；组合处理器不自动整体重试。
- 按需读取 SDK、发现和释放工具、临时上下文材料，以及逐工具 schema 和插件版本诊断。

完整类型插件使用可信宿主 JavaScript。源码检查、任务作用域与 tool-only process 模式不提供 OS 级安全隔离。生成插件不能扩大授权、安装未批准依赖或接管系统授权与预算服务。process 模式明确拒绝 `invokesTools` 回调能力。

## 真实模型评测范围

插件专项包含 12 个任务、3 次重复、2 条路由及 baseline/v2 两组，共 144 个样本。通用任务包含 30 个任务、3 次重复、2 条路由及 baseline/reference/v2 三组，共 540 个样本。基线为提交 `058c3631c51b9f437dfb6dc74d22348a6fcbeedd`。

通用三组使用相同文件工具、任务材料与工作区读写授权。baseline 直接运行归档内核与 `AgentRunner`，从 JSON 断点接续；reference 和 v2 共享当前 `RunService` 与 SQLite，分别使用最小参考循环和当前循环，恢复场景关闭并重开数据库与服务。三组的服务封装与输入组装并不完全相同。插件专项比较各自公开的自扩展入口；基线缺少新的任务插件契约，专项结果不能解释为相同工具能力下的纯循环性能差异。

真实插件专项覆盖 tool、service、context、listener、command、role、provider、api；persona 的注册与释放由确定性测试覆盖，未单独进入真实模型专项。

两组均使用独立任务工作区、固定交错种子和持久请求预算回执。专项与通用结果分别统计，不混合作为成功率。已启动而结果未知的请求保留保守预留，不重放；预检及中止批次只参与预算审计，不参与正式成功率统计。

原始证据分别保存在 [插件专项目录](../evals/reports/composition-final3-20261115/manifest.json) 和 [通用对照目录](../evals/reports/release-composition-final3-20261115/manifest.json)。

网关仅提供路由身份，不能证明底层模型版本固定。免费账单的零分母不能验证 15% 费用增幅门禁。研究任务使用固定本地材料，不能据此判断开放网络检索质量；重复副作用统计限于登记订单场景，其他安全结论依赖确定性测试。

## 角色委派验证

`invoke_plugin` 的超时为 240 秒，与现有子代理入口一致。确定性回归通过真实执行器调用有效角色，委派持续时间超过普通工具的测试期限，并断言仅委派一次；旧实现产生超时，当前实现成功返回。

完整专项中两路由的 role 任务均为 0/3。group/never-stuck 的一个样本成功激活有效角色后在普通 30 秒工具期限超时；另外两个样本的角色 manifest 声明与注册 ID 不匹配；另一条路由的三个样本未进入有效角色调用。角色专项全部失败不能统一归因于超时。

修复后独立验证使用确定性父代理调用创建、启用和角色入口，子代理调用真实路由；每次对子代理首次请求附加 35 秒等待，采用单执行槽位。6/6 次角色调用成功跨过普通超时边界，实际持续 38.3–55.1 秒；完整断言通过 5/6。workbuddy/hy4free 的第 3 次子任务最终答案为空，保留为失败。7 次真实请求均具有完整 usage，计账 11,939 token。此验证核对超时边界、实际子任务结果和槽位调度，不能替代自主创建插件的真实专项或完整性能矩阵。证据见 [角色回归](../evals/reports/composition-role-regression-20261115/REPORT.md)。

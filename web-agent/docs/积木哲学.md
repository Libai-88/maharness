# maharness 积木哲学

模型决定如何完成任务。运行时提供稳定的循环契约、事实、授权、资源和持久状态；工具与可选工作方式通过插件组合。

## 核心与宿主

kernel 定义插件、工具、循环、任务与上下文契约，并提供事件、配置、作用域和调度机制。它不依赖具体业务插件、HTTP 服务或用户界面。默认 Agent 循环通过 runner 工厂接入，可以由实例管理员选择其他实现。

HTTP、SQLite 和 React 构成应用宿主，提供会话、任务、授权和诊断入口。插件通过能力契约扩展宿主；实例级插件可声明导航与 API，任务级插件可提供当前任务的净化面板。

## 组合单位

插件支持 tool、service、context、listener、command、role、provider、persona、api 九类能力。服务通过 ctx.provide / ctx.inject 连接，依赖通过 manifest.requires 声明，事件与资源绑定插件实例的生命周期。

工具声明输入输出 schema、权限和副作用。组合工具通过 ToolContext.invoke 调用宿主工具，每个叶调用单独校验、审批、取消和记账。工具发现、加载和释放管理模型输入中的能力集合。

## 任务内扩展

工作区插件开发授权默认关闭。用户开启后，模型可在当前任务创建候选、验证、启用和停用插件；新增能力在下一次模型请求中可发现。无需另开会话。

run 作用域隔离注册表、服务、事件、配置和存储；workspace 作用域保存用户显式选定的源码版本；instance 作用域由实例管理员安装配置。子任务仅继承明确选择的插件及依赖闭包，使用独立实例。

模型不能扩大权限、安装未批准依赖、接管系统授权与预算服务或更新当前运行实例。框架源码修改采用隔离 worktree、验证、用户审阅采纳与明确重启流程。

## 释放与可信边界

卸载释放通过宿主登记的能力、监听、服务、配置和运行资源。已经发生的文件与外部变更保持原状；数据库回滚也不撤销这些操作。

完整类型插件是可信宿主 JavaScript。作用域、源码检查和 tool-only process 模式均不是 OS 级安全隔离。ToolContext.invoke 使用宿主执行模式，process 模式明确拒绝该回调能力。

# maharness 积木哲学

> **核心理念**：除了 agent 运行时核心，maharness 中所有的一切都是插件。
> 包括前端——它只是插件的一部分。maharness 拥有修改 agent 核心之外的所有能力。
> 整个 maharness 是一块积木：它是什么样子，取决于用户想让它成为什么样子。

## 一、边界划分（唯一不可变的是运行时核心）

| 层级 | 内容 | 可修改性 |
|---|---|---|
| **agent 运行时核心** | kernel/（总线/配置/缓存/预算/Trace/插件加载）、core/chat 的执行循环（agent.ts） | **不可修改**（积木的基座） |
| 内置插件 | core/ 其余全部（search/powershell/tools-fs/self-extend/skills/…） | 可修改（改动经服务重启生效） |
| 用户插件 | plugins/ 现场目录 | 可修改 + 目录监听热重载 |
| **前端** | ui/（界面、主题、图标、面板） | 可修改（经前端构建生效；vite dev 即时生效） |
| 配置 | config.json / .env / DB | 可修改 + 热更新 |

**原则**：核心提供「运行时 + 修改一切的能力」；核心之外的每一块（能力、命令、人设、上下文、API、前端面板）都由插件提供或可被插件/用户修改。

## 二、插件能力全景（八种能力类型）

| 能力 | 用途 | 示例 |
|---|---|---|
| `tool` | LLM 工具 | list_dir / powershell_execute / create_plugin |
| `command` | 斜杠命令（命令面板） | 插件可注册自己的命令 |
| `listener` | 事件监听（钩子） | 插件响应 agent.* 事件 |
| `provider` | LLM Provider | chat 服务消费 |
| `service` | 对外服务实例 | chat 服务 |
| `persona` | 系统提示词片段（L2 层） | 自我扩展规则 |
| `context` | 上下文注入（Context Provider） | 长期记忆 |
| **`api`** | **REST API + 前端面板**（新增） | self-extend 的 /panel 面板 |

**`api` 能力（本次新增，前端插件化的数据通道）**：
- 插件注册 `{ kind: 'api', api: { mount, router } }` → 挂载到 `/api/plugins/<pluginId>/<mount>/...`
- 动态分发：每次请求取当前插件实例——插件热重载后新路由立即生效，无需重启
- 约定：插件提供 `GET /panel` 返回 `{ title, html }` → 前端插件详情页自动渲染为「插件面板」（DOMPurify 净化）
- **由此，插件可以定义自己的前端 UI**——「前端是插件的一部分」不再是口号

## 三、修改能力盘点（maharness 能改什么）

| 对象 | 通道 | 生效方式 |
|---|---|---|
| 插件 | create_plugin / write_file（plugins/） | 目录监听热重载 |
| 内置插件 | write_file（core/） | 服务重启 |
| 前端 | write_file（ui/src/） | 前端构建 / vite dev 热更新 |
| 环境变量 | write_file（.env） | .env 监听 → 刷新 env → 重载全部插件 |
| 配置 | config.json / /api/config | config.changed 热更新 |
| 数据库 | DB API | 即时 |
| 技能 | skills 市场安装/卸载 | 即时 |

**结论**：maharness 拥有修改 agent 核心之外一切的能力，且大部分通道支持热更新——「积木」可塑性完整。

## 四、理念符合性审查（2026-08-16）

| 审查项 | 结论 |
|---|---|
| LLM 工具 100% 来自插件 | ✅ capabilities('tool')，内核零硬编码 |
| 命令插件化 | ✅ command 能力 + 内置/插件命令合并 |
| 人设/上下文插件化 | ✅ persona / context 能力 |
| **插件提供 REST API** | ✅ **本次新增 api 能力**（此前缺失，已纠正） |
| **插件贡献前端 UI** | ✅ **本次新增 /panel 面板机制**（此前缺失，已纠正） |
| server 无业务逻辑 | ✅ 纯路由（历史端点保留，新能力走插件） |
| core/ vs plugins/ 分层 | ✅ 信任分层非能力分层（同一套机制） |
| 自我扩展边界 | ✅ 修正：内核不可动，core/ 其余与 ui/ 可改（此前规则过严） |

## 五、遗留路线（不阻塞，记录）

1. **前端组件级插件化**：目前插件面板是「HTML 片段」级别；未来可支持插件注册 React 组件/路由级页面（需前端动态模块加载机制）。
2. **server 历史端点迁移**：git/config/meta 等端点本质是能力，可逐步迁移为插件（api 能力已就绪，迁移时无需改前端）。
3. **内置命令插件化**：BUILTIN_COMMANDS 可下沉为「核心交互插件」，低优先级。

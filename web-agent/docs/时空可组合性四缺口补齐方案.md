# 时空可组合性四缺口补齐方案

> 范围：内核与插件契约层。四项改动相互独立，可逐项实施、逐项验收。
> 其中缺口一、四为新增能力，缺口二含一处插件侧迁移（已确认调用点仅 1 处），缺口三跨前后端。
>
> **状态：四项均已落地（2026-09-11）。** 回归测试见 `kernel/tests/` 下的
> `plugin-snapshot.spec.ts`、`contract.spec.ts`、`storage.spec.ts`、`nav-contributions.spec.ts`。

## 一、模块图版本化（热重载覆盖依赖）

### 现状与根因

`entryUrl()` 只对**入口文件内容**取哈希。ESM 模块缓存以完整 URL 为键：入口 URL 随内容变化而重建实例，但入口 `import` 的依赖模块 URL 不含哈希，永远命中首次加载的实例。

实测（tsx 4.19 + Node 22.22）：

| 场景 | 结果 |
|---|---|
| 只改依赖文件 | 旧依赖仍在，新依赖代码不可见 |
| 改入口 + 改依赖 | 入口重新执行，依赖仍取旧实例 |

`watch()` 以 `recursive: true` 监听 `plugins/`，文件级事件已能定向触发 reload —— 触发链路是通的，断点在「重新加载拿不到新依赖」。

### 方案：内容哈希 + 同层快照目录

把「插件目录内容」与「加载路径」绑定：目录内容变 → 换一个加载目录 → 整个模块图按内容重建。

快照目录与原目录**同级同深度**（`plugins/tmp-y` → `plugins/tmp-y@965b56b77c`），因此插件内的所有相对导入路径关系完全不变——既包括目录内的 `./dep.ts`，也包括跨目录的 `../../kernel/types.ts`。跨目录导入仍解析到真实内核文件，内核模块保持进程内单例。

#### 1.1 新增 `kernel/plugin-snapshot.ts`

```ts
/**
 * kernel/plugin-snapshot.ts —— 插件模块图的版本化加载
 *
 * ESM 模块缓存以完整 URL 为键，而依赖模块的 URL 无法从外部改写。
 * 本模块的思路是改「加载目录」而不是改 URL：对插件目录按内容取聚合哈希，
 * 把目录镜像到同层同级快照 <parent>/<name>@<hash>/，入口从快照目录加载。
 * 内容一变即换目录名，整张模块图重新实例化；相对导入关系因同层同深度而完全不变。
 */
import { readFileSync, readdirSync, cpSync, rmSync, statSync, existsSync } from 'node:fs';
import { createHash } from 'node:crypto';
import { basename, dirname, join, relative } from 'node:path';

const SOURCE_EXT = /\.(ts|tsx|mts|cts|js|mjs|cjs|jsx)$/;
const SKIP_DIR = new Set(['node_modules', '.git', 'data', 'dist', 'coverage']);
/** 快照目录名：<name>@<10 位十六进制>。扫描与监听据此识别并跳过，避免把快照当插件重复加载 */
export const SNAPSHOT_SUFFIX = /@[0-9a-f]{10}$/;
/** 快照体积上限：超过则不落快照，退回入口级热重载并告警 */
const SNAPSHOT_MAX_BYTES = 8 * 1024 * 1024;

export interface SnapshotInfo {
  /** 内容聚合哈希 */
  hash: string;
  /** 快照目录绝对路径 */
  dir: string;
  /** 是否命中体积上限而放弃快照（true 时 dir === 原目录） */
  skipped: boolean;
}

/** 单文件内容摘要 */
export function fileDigest(file: string): string {
  try {
    return createHash('sha256').update(readFileSync(file)).digest('hex').slice(0, 10);
  } catch {
    return '';
  }
}

/** 目录内源码文件的内容聚合摘要（路径 + 内容，顺序稳定；只统计源码扩展名） */
export function dirDigest(dir: string): string {
  const files: string[] = [];
  const walk = (d: string, depth: number): void => {
    if (depth > 6) return;
    let entries;
    try { entries = readdirSync(d, { withFileTypes: true }); } catch { return; }
    for (const e of entries) {
      if (SKIP_DIR.has(e.name) || SNAPSHOT_SUFFIX.test(e.name)) continue;
      const full = join(d, e.name);
      if (e.isDirectory()) walk(full, depth + 1);
      else if (SOURCE_EXT.test(e.name)) files.push(full);
    }
  };
  walk(dir, 0);
  const h = createHash('sha256');
  for (const f of files.sort()) {
    h.update(relative(dir, f).replace(/\\/g, '/'));
    try { h.update(readFileSync(f)); } catch { /* 读不到的文件不参与版本 */ }
  }
  return h.digest('hex').slice(0, 10);
}

/** 目录总字节数（用于体积上限判断） */
function sizeOf(dir: string): number {
  let total = 0;
  const walk = (d: string, depth: number): void => {
    if (depth > 6) return;
    let entries;
    try { entries = readdirSync(d, { withFileTypes: true }); } catch { return; }
    for (const e of entries) {
      if (SKIP_DIR.has(e.name)) continue;
      const full = join(d, e.name);
      try {
        if (e.isDirectory()) walk(full, depth + 1);
        else total += statSync(full).size;
      } catch { /* 忽略 */ }
    }
  };
  walk(dir, 0);
  return total;
}

/**
 * 为插件目录生成（或复用）快照目录。
 * 目录内容未变时命中既有快照，不重复复制；超体积上限时返回原目录并置 skipped。
 */
export function materialize(pluginDir: string, hash: string): SnapshotInfo {
  const snapDir = join(dirname(pluginDir), `${basename(pluginDir)}@${hash}`);
  if (existsSync(snapDir)) return { hash, dir: snapDir, skipped: false };
  if (sizeOf(pluginDir) > SNAPSHOT_MAX_BYTES) return { hash, dir: pluginDir, skipped: true };
  try {
    const tmp = `${snapDir}.tmp-${process.pid}`;
    rmSync(tmp, { recursive: true, force: true });
    cpSync(pluginDir, tmp, {
      recursive: true,
      filter: (src) => !SKIP_DIR.has(basename(src)) && !SNAPSHOT_SUFFIX.test(basename(src)),
    });
    // 先写临时目录再改名：并发 reload 不会读到半份快照
    rmSync(snapDir, { recursive: true, force: true });
    cpSync(tmp, snapDir, { recursive: true });
    rmSync(tmp, { recursive: true, force: true });
    return { hash, dir: snapDir, skipped: false };
  } catch {
    return { hash, dir: pluginDir, skipped: true };
  }
}

/** 清理目录下除 keep 之外的全部历史快照（插件卸载 / 提交成功后调用） */
export function pruneSnapshots(pluginDir: string, keep: string[] = []): void {
  const parent = dirname(pluginDir);
  const prefix = `${basename(pluginDir)}@`;
  let entries;
  try { entries = readdirSync(parent); } catch { return; }
  for (const name of entries) {
    if (!name.startsWith(prefix) || !SNAPSHOT_SUFFIX.test(name)) continue;
    if (keep.includes(join(parent, name))) continue;
    rmSync(join(parent, name), { recursive: true, force: true });
  }
}
```

#### 1.2 `plugin-loader.ts` 接入

`EntryUrl` 改为由调用方传入加载目录：

```ts
private entryUrl(loadDir: string, entry: string, forceFresh = false): string {
  const filePath = join(loadDir, entry);
  let version = '';
  try { version = dirDigest(loadDir); } catch { /* 读不到 */ }
  if (!version) version = String(Date.now());
  return `${pathToFileURL(filePath).href}?v=${version}${forceFresh ? `&r=${this.factVersion}` : ''}`;
}
```

插件实例增加两个字段，区分「身份目录」与「加载目录」：

```ts
interface PluginInstance {
  dir: string;         // 原目录：manifest 读取、watch 定位、身份标识
  loadDir: string;     // 快照目录：入口 import 的基址
  loadHash: string;    // 本次加载的内容哈希（回滚与清理依据）
  // ...
}
```

`loadPlugin()`：

```ts
const hash = dirDigest(dir);
const snap = materialize(dir, hash);
if (snap.skipped) console.warn(`[plugin] ${id} 体积超过上限，本次改动的依赖文件可能不生效：${dir}`);
inst.loadDir = snap.dir;
inst.loadHash = snap.hash;
const mod = await import(this.entryUrl(inst.loadDir, manifest.entry));
```

`reloadInternal()` 的事务语义因此增强为**目录级回滚**：

```ts
// 阶段 1：回收旧实例效果（旧快照目录保留）
await this.stopInternal(inst);
// 阶段 2：新快照 + 加载
const hash = dirDigest(dir);
const snap = materialize(dir, hash);
const fresh: PluginInstance = { ..., loadDir: snap.dir, loadHash: snap.hash };
try {
  const mod = await import(this.entryUrl(snap.dir, freshManifest.entry, forceFresh));
  // ... runLoad / startInternal / 提交
  this.registry.set(id, fresh);
  // 提交成功后清理历史快照，仅保留当前一份
  pruneSnapshots(dir, [snap.dir]);
} catch (err) {
  // 回滚：用【上一份快照】重新加载——依赖状态也一并回到旧版本
  await fresh.scope.dispose();
  const rollback = { ..., loadDir: inst.loadDir, loadHash: inst.loadHash };
  await this.runLoad(rollback);
  await this.startInternal(rollback);
  this.registry.set(id, rollback);
  pruneSnapshots(dir, [inst.loadDir]);   // 保留回滚所依赖的旧快照
  this.bus.emit(EventBus.event('plugin.error', { id, error: msg, rollback: true }));
}
```

插件彻底卸载（disable / 目录删除）时：`pruneSnapshots(dir)` 清空全部快照；若插件目录本身已消失，父目录扫描时按 `SNAPSHOT_SUFFIX` 兜底清理孤儿快照。

#### 1.3 扫描与监听过滤 + 孤儿回收

三处跳过快照目录，否则会被当作新插件重复加载：

```ts
// scanDir() / rescanUser()：目录遍历
if (SNAPSHOT_SUFFIX.test(e.name)) continue;

// onFileChange()：快照的创建/删除会触发监听事件，直接忽略
if (filename && SNAPSHOT_SUFFIX.test(filename.split('/')[0])) return;
```

`scanDir()` 顺带回收**孤儿快照**（插件目录已消失、快照失去归属）：按目录名还原 owner，owner 不存在即删除——否则磁盘上会累积无主副本。

#### 1.4 配套调整

- 原 `entryHash` 字段与 B9 告警删除（"代码改动可能未生效"的前提已不成立）。
- `.gitignore` 增加 `core/*@*/` 与 `plugins/*@*/`；`tsconfig.json` 的 `exclude` 增加 `**/*@*`——快照目录是运行时产物，既不入库也不参与类型检查。
- `plugin-authoring/SKILL.md` 中「插件文件改动需重启进程」的契约条目替换为：插件可多文件组织，任何源码文件改动经目录监听自动生效。

### 边界与代价

| 项 | 说明 |
|---|---|
| 已验证 | 同层快照下，依赖更新生效、跨目录导入（`../../kernel/types`）正确、内核模块保持单例 |
| 磁盘 | 每插件保留 1 份当前快照（提交后即清理历史）；源码量在数十 KB 级 |
| 首次加载 | 多一次目录复制（毫秒级，仅源码文件） |
| 体积上限 | 默认 8 MB；超限退回入口级热重载并打印告警，不会静默失败 |
| 目录可出现临时项 | `plugins/` 与 `core/` 下会出现 `<name>@<hash>` 目录。已由扫描/监听过滤，且提交后仅存一份 |
| 插件对自身目录的假设 | 快照目录内是完整副本（含非源码资源），`import.meta.url` 与相对资源读取仍有效；但代码不应把绝对路径写死到运行期数据 |

### 验收

新增 `kernel/tests/plugin-snapshot.spec.ts`：

1. `dirDigest` 对同一目录稳定、对任一源码文件内容敏感、忽略 `node_modules` 与 `@hash` 目录；
2. `materialize` 生成同层快照且内容与源目录一致；同哈希二次调用不重复复制；
3. 超体积上限时返回原目录且 `skipped = true`；
4. `pruneSnapshots` 只保留指定目录。

`loader.spec.ts` 增补三条端到端断言：

5. 插件 A 依赖 B，改 B → reload → 新 B 行为生效（当前回归：无效）；
6. 插件目录内的跨目录导入在快照加载后仍解析到同一内核模块实例；
7. 新版本加载失败 → 回滚到上一份快照，且旧依赖行为同样恢复（当前回归：仅入口模块回滚）。

`scripts/selftest.ts` 的 `[compose]` 段增补：写入依赖文件新版本 → reload → 断言新行为生效。

## 二、可逆性强制化（封堵 `ctx.bus` 旁路）

### 现状与根因

`PluginContext.bus` 直接暴露内核 `EventBus`，插件调 `ctx.bus.on()` 注册的监听器不进入 `EffectScope`，卸载后残留。当前插件侧统计：`ctx.bus.on` 1 处（`core/evolve`，手写 `busOff` 兜底），`ctx.bus.emit` 9 处（发射无回收需求，不受影响）。

类型层面无法阻止旁路，运行时门面也不存在——可逆性承诺因此依赖作者自觉。

### 方案

三层同时收口：类型收窄 → 运行时门面 → 契约测试。

#### 2.1 `kernel/types.ts`：新增 `PluginBus`，收窄 `PluginContext.bus`

```ts
/**
 * 插件可见的事件门面：只出不进。
 * 订阅必须走 ctx.on（自动退订，进入 EffectScope）；on / once / onPhase 一律不暴露——
 * 裸监听会绕过逆元栈，卸载后泄漏，是本项目「结构性可逆」承诺的唯一破口。
 */
export interface PluginBus {
  emit(e: Event): void;
  emitAsync(e: Event): Promise<void>;
  /** v3 五语义派发：短路 / 并发 / 洋葱中间件 */
  serial<T = unknown>(e: Event<T>): Promise<T | boolean | null | undefined>;
  bail<T = unknown>(e: Event<T>): T | boolean | null | undefined;
  parallel(e: Event): Promise<void>;
  waterfall<T = unknown>(type: string, ...args: unknown[]): Promise<T>;
}

export interface PluginContext {
  // ...
  bus: PluginBus;   // 由 EventBusLike 收窄
  // ...
}
```

#### 2.2 `kernel/plugin-loader.ts`：`buildContext` 用门面替换裸总线

```ts
const pluginBus: PluginBus = {
  emit: (e) => this.bus.emit(e),
  emitAsync: (e) => this.bus.emitAsync(e),
  serial: (e) => this.bus.serial(e),
  bail: (e) => this.bus.bail(e),
  parallel: (e) => this.bus.parallel(e),
  waterfall: (type, ...args) => this.bus.waterfall(type, ...args),
};

return {
  pluginId: inst.manifest.id,
  kernel: this.ctxBase.kernel,
  paths: this.ctxBase.kernel.paths,
  bus: pluginBus,          // was: this.bus
  // ...
};
```

`onPhase`（洋葱中间件）不进入插件门面；当前插件栈零使用，如后续确有需要，按同一模式补 `ctx.onPhase()` 并纳入 scope。

#### 2.3 迁移 `core/evolve/index.ts` 的唯一旁路

```ts
// before
const off = ctx.bus.on('agent.run.finished', (e) => { ... });
busOff = () => { try { off(); } catch { /* 已卸载 */ } };

// after
ctx.on('agent.run.finished', (e) => { ... });   // 自动退订
```

模块级 `busOff` 变量与 `onUnload` 中的清理调用一并删除。

#### 2.4 契约测试 `kernel/tests/contract.spec.ts`

静态扫描 `core/**/*.ts` 与 `plugins/**/*.ts` 源码，命中即失败：

```
/ctx\.bus\.(on|once|onPhase)\s*\(/
```

并在 `PluginLoader` 上新增测试辅助 `contextOf(id: string): PluginContext | undefined`，断言门面不含 `on`：

```ts
const facade = kernel.plugins.contextOf('tmp-x');
assert.strictEqual(typeof (facade!.bus as Record<string, unknown>).on, 'undefined');
```

### 验收

1. 迁移 `evolve` 前执行 `npm run typecheck` 应报错（类型层拦截生效）；
2. `contract.spec.ts` 通过，且人为插入 `ctx.bus.on(...)` 时确实失败；
3. `evolve` 行为不变：`disable` 后再发 `agent.run.finished`，无回调触发（scope 已回收）。

## 三、前端组件级组合（插件 UI 模块协议）

### 现状

插件经 `nav` 声明拿到一页，形态限 `iframe`（完整页面）与 `panel`（净化 HTML 片段）。两者都无法与宿主状态互操作：拿不到主题变更与会话事件，没有统一 API 客户端，也无法复用宿主 React 实例。

### 方案

新增第三种 nav 模式 `module`：插件提供一个浏览器原生 ESM 模块，导出挂载函数，宿主注入 React 与能力接口。

#### 3.1 契约

`plugin.json`：

```json
{
  "nav": {
    "label": "看板",
    "icon": "todo",
    "order": 50,
    "mode": "module",
    "module": "index.js"
  }
}
```

`nav.module` 是插件目录 `ui/` 子目录内的相对路径（内核按 `/api/plugins/<id>/ui/<module>` 托管）。

插件模块 `ui/index.js`：

```js
export function mount(container, host) {
  const { React, ReactDOM } = host;
  const root = ReactDOM.createRoot(container);
  root.render(React.createElement(Board, { api: host.api }));
  return () => root.unmount();      // 卸载函数：标签页切走时调用
}
```

`HostApi`（宿主注入，插件对外交互的唯一通道）：

```ts
export interface PluginHostApi {
  pluginId: string;
  React: typeof import('react');
  ReactDOM: typeof import('react-dom/client');
  /** 带前缀与错误规整的 HTTP 客户端，默认指向 /api/plugins/<id> */
  api: {
    get<T>(path: string): Promise<T>;
    post<T>(path: string, body?: unknown): Promise<T>;
  };
  toast: { success(msg: string): void; error(msg: string): void };
  theme: { current: 'light' | 'dark'; onChange(cb: (t: string) => void): () => void };
  /** 订阅后端 SSE 事件（白名单在宿主侧维护） */
  subscribe(event: string, cb: (data: unknown) => void): () => void;
  openExternal(url: string): void;
}
```

React 由宿主注入而非插件自带，避免双 React 实例。

#### 3.2 内核与服务端

- `NavDef.mode` 扩展为 `'iframe' | 'panel' | 'module'`，新增 `module?: string`。
- `navContributions()` 对 module 模式用 `fileDigest()`（见 §1.1）计算 UI 入口内容哈希，输出 `moduleUrl`，UI 改动即时生效：

```json
{ "key": "plugin:todo", "mode": "module", "moduleUrl": "/api/plugins/todo/ui/index.js?v=a1b2c3d4e5" }
```

- `server/routes/plugins.ts` 新增 `GET /api/plugins/:id/ui/*`：
  - 只服务插件目录 `ui/` 子目录下的 `.js / .mjs / .css / .map`；
  - 路径规范化后必须落回该目录内（防目录穿越）；
  - `Cache-Control: no-store`（版本参数已保证缓存正确性）。

#### 3.3 前端

新增 `ui/src/components/PluginModuleView.tsx`：

```tsx
export default function PluginModuleView({ item }: { item: PluginNavItem }) {
  const ref = useRef<HTMLDivElement>(null);
  const [error, setError] = useState<string | null>(null);
  useEffect(() => {
    let unmount: (() => void) | undefined;
    let alive = true;
    void (async () => {
      const mod = await import(/* @vite-ignore */ item.moduleUrl!);
      if (!alive || !ref.current) return;
      unmount = mod.mount(ref.current, buildHostApi(item.pluginId));
    })().catch((err: unknown) => setError(err instanceof Error ? err.message : String(err)));
    return () => { alive = false; unmount?.(); };
  }, [item.moduleUrl]);
  // 容器 + 与 panel 模式共用的错误边界
}
```

`App.tsx` 的插件分支按 `item.mode` 三分派；已有 `PluginPageBoundary` 继续兜住模块渲染异常。

#### 3.4 安全边界

`module` 模式与宿主同源、同一 JS realm，**没有沙箱**——插件能触碰 `window`、DOM 与任何同源接口。因此：

- `module` 模式适用于受信任插件（本地编写 / 用户自行安装）；
- 来源不可信的插件继续用 `iframe` 模式（`sandbox` 属性已限制其权限）；
- `plugin-authoring/SKILL.md` 写明这条选择规则。

### 验收

1. `nav-contributions.spec.ts` 增补：module 模式投影含 `moduleUrl`，且随 UI 文件内容变化；
2. server 测试：`/api/plugins/:id/ui/../../kernel/index.ts` 返回 404；
3. ui e2e：临时插件以 module 模式挂载组件，切换标签页后 `unmount` 被调用（无残留 DOM）；
4. 主题切换时 `host.theme.onChange` 回调被触发。

## 四、界外效应的收敛与补偿台账

### 现状

`EffectScope` 追踪界内效应（能力/订阅/服务/配置）；界外效应（文件、DB、网络、子进程）不追踪、不枚举、不可撤销。插件写文件没有专属目录约束，卸载时也没有「它动过什么」的清单。

### 方案

把不可逆的界外效应收敛为可枚举、可回收的插件私有资源，把无法回收的部分变成可见台账。

#### 4.1 插件私有存储 `ctx.storage`

```ts
export interface PluginStorage {
  /** 插件专属目录：<data>/plugins/<pluginId>（内核创建，插件独占） */
  readonly dir: string;
  read(name: string): string | null;
  write(name: string, content: string): void;
  list(): string[];
  remove(name: string): void;
}
```

加载时创建目录并注入。`plugin-authoring/SKILL.md` 规定：插件持久化数据一律写 `ctx.storage`，不写 `paths.data` 根目录、不写自身代码目录。

#### 4.2 界外发射台账 `ctx.outbound`

```ts
export interface OutboundRecord {
  /** 发射类型 */
  kind: 'file' | 'http' | 'db' | 'proc';
  /** 人可读描述：路径、URL、表名、命令行 */
  detail: string;
  /** 是否可由插件自行补偿 */
  compensable?: boolean;
}

export interface PluginContext {
  outbound: { record(rec: OutboundRecord): void };
}
```

实现：

- 每次 `record` 追加一行到 `<data>/outbound/<pluginId>.jsonl`，并广播 `plugin.outbound` 事件（复用既有总线通道，不新增轨迹步骤枚举）；
- `stopInternal()` 汇总本生命周期的发射条数，写入 `plugin.reverted` 事件负载：`{ id, effects: N, outbound: M }`；
- 台账随插件 id 归档，不做自动截断——它记录的是不可逆动作，删减反而丢失审计价值。

#### 4.3 卸载清理策略 `manifest.cleanup`

```ts
/** 卸载时对插件私有存储的处理：keep 保留（默认）/ archive 归档到 <data>/archive/<id>-<ts>/ / purge 清除 */
cleanup?: 'keep' | 'archive' | 'purge';
```

`uninstall(id)`（删除插件目录）与扫描发现插件目录已消失时执行对应策略，并发出 `plugin.cleanup { id, strategy, dir, outbound: M }` 事件供管理面展示。
**停用（disable）与热重载不清理**——插件仍在役或可能被重新启用，数据不应在此时消失。

#### 4.4 边界

文件（`ctx.storage` 内）与插件自建表可回收；HTTP 调用、外部系统写入、子进程副作用不可撤销。台账的作用是让「不可逆」从隐式变成显式：卸载摘要给出清单，需要回退时由 Agent 或用户按清单处理。

### 验收

1. 新增 `kernel/tests/storage.spec.ts`：写入落在 `<data>/plugins/<id>`；目录删除式卸载按 `purge` 清除、按 `keep` 保留；
2. `outbound` 台账：`ctx.outbound.record()` 后 `<data>/outbound/<id>.jsonl` 有对应行，`plugin.reverted` 负载含 `outbound` 计数；
3. `selftest` 的 `[compose]` 段增补：注册 storage + 记录一次 outbound → disable → 断言目录策略执行、摘要计数正确。

## 六、回归风险清单

| 风险 | 影响面 | 缓解 |
|---|---|---|
| 快照目录被当作插件重复加载 | 插件注册表 | `rescanUser` 与 `onFileChange` 双处按 `SNAPSHOT_SUFFIX` 过滤；`pruneSnapshots` 兜底清理孤儿 |
| 快照写入触发监听自激 | 文件监听 | `onFileChange` 首行忽略 `@hash` 前缀事件 |
| 超大插件目录复制开销 | 加载延迟 | 8 MB 上限；超限退回入口级并告警 |
| 并发 reload 读到半份快照 | 模块完整性 | 先写 `.tmp-<pid>` 再改名 |
| `ctx.bus` 收窄为破坏性类型变更 | 插件源码编译 | 插件侧仅 1 处调用，随方案迁移；外部插件编译期即报错，优于运行期泄漏 |
| module 模式无沙箱 | 安全边界 | 文档明确「module = 受信任插件」，不可信来源走 iframe sandbox |
| `cleanup: 'purge'` 误删数据 | 插件数据 | 默认 `keep`；`purge` 需显式声明；`archive` 提供中间选项 |

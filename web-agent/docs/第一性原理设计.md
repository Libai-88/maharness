# maharness 第一性原理设计手册

> 原则：**从本质出发解决问题**。每个部分先问「它存在的本质原因是什么」，再从本质推导设计，拒绝惯例与装饰。
> 配套文档：docs/思维链研究.md（提示词层的研究依据）。

## 总纲：maharness 的本质

maharness 是一个**通过工具改变真实世界的自主软件体**。由此推出全系统的四个第一性原理：

1. **认知第一性**：模型是 token 预测器，英文语料的推理路径最深 → 英文思考 + 哲学框架引导思维形态；
2. **行动第一性**：每一步都在改变真实世界 → 观察先于断言、验证先于交付；
3. **经济第一性**：思考与工具调用都有真实成本 → 如无必要，勿增实体（奥卡姆剃刀）；
4. **认识论**：知识只能来自观察，工具即感官 → 未知必须命名，臆测必须禁止。

## 分系统设计（本质 → 原则 → 落地）

### 1. L0 提示词系统（core/chat/index.ts）

- **本质**：提示词不是「告诉模型该做什么」，而是**引导 token 的生成路径**——模型的推理质量取决于推理路径的形态。
- **原则**：认知第一性 → 用英文与哲学框架稳定思维形态；经济第一性 → 思考分级与预算。
- **落地**：思维宪章（英文 + "We need" + 第一性原理/奥卡姆/斯多葛三原则）、思考分级、信息缺口检查、禁止无依据自纠、品牌特调（羊 × 牧羊犬：以工具为感官，以行动完成使命，以诚实回报信任）。

### 2. Agent 执行循环（core/chat/agent.ts）

- **本质**：Agent 不是「对话」，是**贝叶斯式的信念更新循环**——决策（假设）→ 行动（实验）→ 观察（证据）→ 更新信念；直到信念足以回答，或证据耗尽。
- **原则**：行动第一性 → 观察先于断言；认识论 → 工具结果是唯一可接受的事实来源。
- **落地**：思考-行动-观察循环、工具结果回填为 system/tool 消息、截断时显式告知「结果已截断」（防「看不到全貌却以为看到了全部」）、连续失败注入自适应提示。

### 3. 认知资源管理（kernel/budget.ts）

- **本质**：认知资源（token/轮次/思考）是稀缺的，且**LLM 不会自觉节约**——节约必须由 harness 强制执行，而不是寄望于模型的自觉。
- **原则**：经济第一性 → 按任务本质分配资源。
- **落地**：重工具配额（子代理窗口限次）、任务画像（类型/轮数/成本/成败，自适应数据源）、**按任务类型分配思考预算**（`reasoningBudgetFor`：代码 ×1.5、问答 ×0.5、观察驱动任务 ×0.75——代码给足思考空间，问答防止过度思考）。

> **思考预算的本质（v2 修正）**：预算限制的是**空转**（重复推理、原地打转），而不是**有效思考**（拆解、分析证据、规划下一步）。因此采用双轨设计：
> - **单轮预算**（默认 800 token ≈ 600 英文词）：单轮 reasoning 超限即提示收敛——防单轮空转；
> - **总量预算**（默认 3000 token）：跨轮累计，防「每轮 600 词 × 5 轮」式的多轮空转绕过单轮限制；
> - **降级提示保留推进出口**：「若确有新信息可观察（调工具）或新路径可尝试，继续推进；若只是在重复已有推理，给出当前最佳结论」——不会打断复杂任务的深度推理，只打断原地打转。

### 4. 三层缓存（kernel/cache.ts）

- **本质**：重复计算是浪费的本质——同一问题的答案、同一工具的结果、同一段 prompt 都是**已被观察过的现实**，不值得再次付出代价。缓存不是优化，是「不重复劳动」的纪律。
- **原则**：「重复」有三种本质不同的形态，故分三层：
  - **L1 语义缓存**＝问题的重复（同义提问无需再问 LLM）——bigram Dice 相似度，免外部 API；
  - **L2 工具结果缓存**＝观察的重复（同一工具+同一参数+文件未变 = 同一事实）——hash+mtime/size 校验；
  - **L3 prompt 前缀缓存**＝token 的重复（多轮前缀不变，吃 provider KV cache）——消息只追加不重写。
- **落地**：见 cache.ts；阈值/TTL 可配置（cache.l1Threshold / cache.l2TtlMin），热更新。

### 5. 上下文管理（server/context.ts）

- **本质**：上下文是**稀缺的注意力窗口**——塞入的信息要么帮助决策，要么稀释决策。
- **原则**：只放对下一步决策有用的信息；遗忘（截断）是记忆的艺术——**被截断的信息必须被命名**，否则模型会产生「缺失记忆」的错觉。
- **落地**：按预算截断（system 保底、最新消息完整保留）、截断注入说明消息、context.maxTokens 可配置。

### 6. 插件体系（kernel/plugin-loader.ts）

- **本质**：Agent 的能力边界必然随需求生长——若能力与内核耦合，每次生长都要重写内核。
- **原则**：变化与稳定的分离 → **薄内核 + 全插件化**。内核只做三件事：事件总线、配置、资源管理。
- **落地**：能力注册表（tool/listener/command/provider）、现场写现场加载、插件自述自动进入系统提示词（L2 层）、卸载即消失。

### 7. 可观测性（kernel/trace.ts）

- **本质**：不可观测 = 不可改进。Agent 的每一次决策、动作、代价都必须留下记录，否则「优化」只是猜测。
- **原则**：全程可观测——LLM 调用、工具执行、缓存命中、审批、预算降级全部入 Trace。
- **落地**：Trace 环形缓冲 + 实时 SSE + 统计接口 + JSONL 导出。

### 8. 安全与审批（agent.ts + routes.ts）

- **本质**：Agent 拥有改变真实世界的能力，**权力必须可审计、可撤回**。
- **原则**：破坏性操作的执行权属于用户，不属于模型；审批不可绕过、不可诱导。
- **落地**：写操作触发审批、审批全程入 Trace、超时自动拒绝、拒绝后结果如实回填给模型（模型不能假装执行过）。

### 9. 工具层（core/tools-fs 等）

- **本质**：工具是 Agent 的感官——**感官必须诚实**：只报告观察到的事实，不粉饰、不猜测。
- **原则**：工具描述附带风险/成本/输出格式标签（annotateToolDef），让模型在调用前就知道代价与边界。
- **落地**：`【风险:…|成本:…|需审批】` 前缀 + 输出格式说明；沙箱路径约束。

### 10. 前端 UI

- **本质**：界面是 Agent 的「身体语言」——让用户**看见思考、看见行动、看见代价**，信任由此建立。
- **原则**：诚实呈现（真实状态、真实数据、真实反馈），品牌统一（羊意象），交互即功能（无假按钮）。
- **落地**：思考块/工具卡/轨迹面板/审批卡实时呈现；前后端状态枚举严格对齐。

## 设计决策自检清单

每个新功能上线前，问四个问题：

1. **认知**：这个功能是在引导推理路径，还是在堆砌指令？（后者通常无效）
2. **行动**：每一步是否有观察支撑？是否会改变真实世界而未经验证？
3. **经济**：为此付出多少 token/调用/轮次？有没有更短的路径？
4. **诚实**：用户能否看到真实状态？系统是否在假装知道什么？

四问皆过，才符合 maharness 的第一性原理。

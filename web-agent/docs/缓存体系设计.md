# maharness 缓存体系设计

> 目标：让「已被观察过的现实」不被重复计算——逼近 100% 命中率。
> 借鉴：GPTCache（语义缓存）、Redis/Caffeine（TTL 与淘汰）、prompt cache 分层（KV cache）、W-TinyLFU（访问频率）。

## 一、第一性原理：重复有三种本质

| 层 | 重复的本质 | 缓存什么 | 失效策略 |
|---|---|---|---|
| **L1 语义缓存** | 问题的重复 | 同一含义问题的 LLM 答案 | TTL 24h + promptKey 隔离 |
| **L2 工具结果缓存** | 观察的重复 | 同一工具+同一参数的返回 | TTL 30min + 文件 mtime/size 校验 |
| **L3 prompt 前缀缓存** | token 的重复 | 多轮对话的公共前缀（provider KV cache） | 消息只追加不重写，前缀稳定 |

## 二、L1 语义缓存：轻量语义归一化（自研）

**核心洞察**：中文同义改写后，全文本 bigram 重合率天然低（实测 0.45-0.71），阈值 0.85 时**永远无法命中**。语义匹配必须忽略表面措辞：

1. **内容词过滤**（`contentWords`）：去标点空格 → 去中文功能词（的/了/吗/是/什么/帮我…）→ 内容词序列。实测相似度大幅提升：Python 释义 0.563→0.846、PowerShell 释义 0.683→0.722。
2. **精确匹配优先**：归一化后全等的重复提问直接命中（O(1)），不走相似度。
3. **动作方向校验**（`actionGroups`）：内容相似但动作不同（写 vs 读）绝不能串答案——动词归一为语义类别（query/write/delete/execute），命中前比对类别集合。实测拦截「写快排→读快排」误命中（相似度 0.875 被正确拒绝）。
4. **阈值 0.58**：实测命中 0.667-0.846 的同义改写，拒绝 0.513 弱相关与 0.0 无关。
5. **命中学习**：命中时回填当前措辞——缓存簇随使用扩展，第 3、4 种说法连续命中。
6. **promptKey 隔离**：systemPrompt 指纹分区——人设/插件/思考语言变化不串用旧答案。

**可选升级路径**：配置 EMBEDDING_* 后自动切换向量语义匹配（余弦 ≥ 0.95），覆盖完全改写的同义问题（内容词 bigram 无法覆盖的 0.0 情形）。

## 三、持久化：缓存必须比进程活得久

**洞察**：进程内缓存重启即清零，命中率必然归零——「逼近 100%」的前提是跨重启保留。

- 落盘 `data/cache.json`（L1 特征 + L2 值，防抖 5s 保存，`kernel.stop()` 时强制落盘）
- 启动时恢复未过期条目（过期条目直接丢弃）
- 实测：写入 → 重启 server → 同义改写命中（cached: True，跨进程）

## 四、L2 工具结果缓存

- 已接入：`list_dir` / `read_file`（key = hash(工具+参数+mtime+size)，文件变更即时失效）、`web_search`（TTL 10min，v2 命名空间）
- 安全边界：只缓存**只读/确定性**工具；写操作永不缓存
- TTL 是防膨胀底线（文件类有 mtime 校验，TTL 只是保险）

## 五、L3 prompt 前缀缓存

- 消息**只追加不重写**（历史不变、新消息追加）→ provider KV cache 前缀稳定命中
- 注入类消息（英文思考 Reminder、记忆、预算提示）固定在末尾，不破坏前缀
- 统计：每轮与上一轮的公共前缀 token 数（`sharedPrefixTokens`）

## 六、命中率度量

- Trace：每次命中记录 `cache_hit` 步骤（L1/L2 均可观测）
- Stats：L1 hits/misses/rate、L2 统计、overall（served/total/rate）、节省成本
- 前端：轨迹面板实时命中率 + 统计页三层缓存卡

## 七、实测结果

| 场景 | 结果 |
|---|---|
| 同义改写命中（列出↔查看） | ✅ cached: True |
| Python 释义（0.846 相似度） | ✅ 命中 |
| 写→读 方向拦截 | ✅ 不误命中 |
| 无关问题（0.0） | ✅ 不误命中 |
| 跨进程重启 | ✅ 磁盘恢复后命中 |
| 精确重复提问 | ✅ O(1) 命中 |

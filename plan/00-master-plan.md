# maharness 总体优化计划

## 目标

把 maharness 从“能力齐全的插件化 Agent 原型”推进为可验证、可恢复、可扩展、可安全运行的 Agent Harness。所有工作以 `web-agent` 当前代码为事实基线，按 P0 至 P3 分阶段交付。

## 基线

- 后端：`npm test` 878 tests passed；`npm run typecheck` 通过；`npm run eval:ci` 27/27 通过，安全攻击阻断 4/4；`npm run selftest` 91/91 通过。
- 前端：`ui` 目录 `npm run typecheck`、`npm run build` 通过；`npm run e2e` 14/14，通过气泡交互、引用回复、任务验收证据、审批批准/拒绝、当前 run 的 Trace 实时展示/类型筛选/JSONL 导出及断点恢复 UI/API 契约回归；子代理、并行、插件 UI 和服务端审批/恢复集成仍待覆盖。
- 架构：内核、插件加载、服务接管、Agent 循环、工具审批、Trace、缓存、记忆、计划、MCP 和自扩展均已存在。
- 历史缺陷批次已完成：缺陷清单记录 Batch 1-5、F3 和新增 B17/B18 均已验收；安全、配置、Trace 噪声、压缩、缓存、前端事实问题已有回归护栏。
- 当前边界：插件完全信任；无多用户/多租户；不适合公网或局域网共享；`core/` 与现场插件的热加载边界仍需产品化；关键 Agent 流程 E2E、任务结果验证、长任务恢复和开发者生态仍不完整。
- 历史缺陷证据与已完成批次见 `maharness-缺陷清单与修复方案.md`；本目录只规划后续优化，不重复安排已完成修复。

## 依赖 DAG

```text
P0 安全/正确性 ─┬─> P1 任务质量 ─> P1 Trace 调试 ─> P1 UI E2E
                ├─> P1 长任务恢复
                └─> P0 文档事实收口
P1 评测基座 ───────> 所有 P1/P2 功能验收
P0 插件信任边界 ──> P2 插件生态
模型契约 ─────────> 上下文/缓存可解释性
API 鉴权/租户边界 ─> P3 部署
```

## 阶段出口

### P0 出口

历史敏感文件、审批、SSRF、MCP、密钥和 HTTP 控制面缺陷继续保持回归全绿；插件信任和任务完成语义有显式契约；质量门禁覆盖所有后续阶段；基线命令全部通过。

### P1 出口

任务有完成判定和失败分类；Trace 可过滤、关联、重放和导出；关键 UI 流程有 Playwright 覆盖；长任务可 checkpoint、恢复、取消、幂等；评测报告能比较版本和回归。

### P2 出口

插件/技能有 manifest、权限、兼容性和评测契约；Provider 路由可解释；上下文压缩、记忆和缓存可解释并可观测。

### P3 出口

API 鉴权、数据迁移、备份恢复、部署清单和运维指标达到可控上线条件；公网部署前完成威胁模型复核。

## 全局验收清单

- `npm test`

- `npm run ui:typecheck`
- `npm run ui:build`
- `npm run e2e`

- 故障测试：Provider 超时、工具失败、插件坏版本、进程重启、断点恢复、重复提交。
- 文档检查：API、数据库、内核件数、配置默认值、E2E 列表和已知边界均从代码生成或逐项核对。

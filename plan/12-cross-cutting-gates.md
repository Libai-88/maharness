# 跨领域执行门禁

关联登记项：UX-01 至 UX-05、AG-01 至 AG-06、OB-01 至 OB-06、QA-01 至 QA-07、SEC-01 至 SEC-07、PL-01 至 PL-06、MD-01 至 MD-06、CT-01 至 CT-07、LR-01 至 LR-06、API-01 至 API-08、DX-01 至 DX-07。

## 适用范围

本门禁适用于 UX、AG、OB、QA、SEC、PL、MD、CT、LR、API、DX 的每个变更；登记册中的每个条目都必须引用本门禁并提供对应证据。

## 变更前基线

记录代码版本、数据库 schema、事件 schema、配置默认值、相关指标基线和回滚开关；确认变更编号、负责人、依赖和影响范围。

## 每个变更必须回答

1. 影响哪个事件、服务、数据表或插件契约？
2. 失败、取消、重试、重启和回滚如何处理？
3. 是否新增权限、网络、文件、进程或模型成本？
4. 是否有单测、集成、golden 或 E2E 证据？
5. 文档、指标、迁移和兼容策略是否同步？

## 发布门禁

- P0/P1 安全和正确性回归全绿。
- `npm test`、`npm run typecheck`、`npm run eval`、`npm run ui:typecheck`、`npm run ui:build`、`npm run e2e` 全绿。
- 新增 API/事件/表/配置有 schema、版本和迁移说明。
- 任何不可逆外部副作用都有审批、幂等键或补偿记录。
- Trace 能定位失败，指标能证明性能/成本没有超阈值。

## 关闭标准

计划只有在实现、自动化验证、文档事实和回滚路径都提交后才可关闭；“代码已写但没有失败演练”视为未完成。

## 证据格式

每个登记项关闭时必须记录：实现提交、测试命令及结果、运行环境、指标对比、迁移/兼容说明、文档链接和回滚步骤。证据缺一项则保持“待执行”。

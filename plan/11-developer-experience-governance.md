# 开发者体验与项目治理

关联登记项：DX-01、DX-02、DX-03、DX-04、DX-05、DX-06、DX-07。

## 现状证据

仓库已有 README、架构文档、缺陷清单、selftest、单测和 eval，但文档曾出现内核件数、API、SQL 表、配置默认值和 E2E 断言漂移；版本信息分散。

安全文档映射门禁已接入 CI：`npm run check:threat-model` 检查威胁模型引用文件存在，并确保 `test:security` 的每个 spec 都映射在威胁模型中；负向验证确认缺失测试文件会使命令失败。

## 目标

新贡献者能在半小时内运行、理解边界、添加插件和写测试；代码、文档、评测和版本来源一致。

## 执行

1. 将架构、API、数据库、配置和事件契约改为可生成或带事实检查的文档。
2. 统一版本来源、变更日志、迁移说明和弃用策略。
3. 建立 CI：格式/类型/单测/eval/UI build/E2E/安全回归/文档事实检查。
4. 提供插件脚手架、调试日志级别、测试 fixture、录制回放和故障排查手册。
5. 维护 ADR、威胁模型、兼容矩阵和发布检查清单。

## 验收

新插件示例可复制运行；文档事实检查能发现 API/表/配置漂移；PR 必须通过分层门禁；每次发布有可回滚版本和迁移说明。

## 依赖、风险与指标

依赖各领域稳定的 schema 和命令入口，先收敛契约再自动生成文档。自动生成物标注来源并由 CI 检查，禁止手工编辑生成片段。目标：干净 checkout 到测试通过 < 15 分钟；文档事实检查覆盖 API、表、配置和事件；CI 核心门禁成功率 >= 98%。生成器误报时只允许对具体规则临时豁免，并设到期时间。

## 范围、测试与完成定义

范围包括根 README、架构/API/DB/事件/配置文档、版本与迁移说明、CI、ADR、脚手架、fixture 和发布清单。

测试使用干净 checkout 验证安装、核心测试、插件示例、文档生成、事实漂移和分层 CI；诊断脚本必须标注为诊断，不替代正式回归。

DX-01 至 DX-07 均有可复现命令、文档事实检查、CI 证据、版本兼容说明和回滚路径后关闭。

DX-01 验收（2026-11-01）：`web-agent/docs/DEVELOPMENT.md` 提供唯一从零入口——安装（`npm ci` 双仓）、核心验证（typecheck + 905 项单测）、完整验证（selftest/eval:ci/build/安全回归/威胁模型）、开发模式、常见问题与文档索引。干净 checkout 实测（Windows 11，2026-11-01）：`npm ci` 4s + `npm ci --prefix ui` 6s + `npm run typecheck` 5s + `npm test` 37s = **52 秒**，`npm run selftest` 26s，远低于 15 分钟验收门槛；CI runner（ubuntu-latest）完整门禁约 6 分钟同样达标。文档步骤与 CI workflow 逐条对应，命令即 CI 步骤。回滚：删除 `docs/DEVELOPMENT.md` 并还原登记状态。

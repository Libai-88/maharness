# ADR 0011：热点度量改用复杂度预算

## 背景

P2-5 的拆分判据来自"文件行数"。行数被两件事污染：一是格式化宽度（同一文件在 140 列下从 1,922 涨到 2,121 行，实际代码没变）；二是长注释与长字面量。结果是"哪里需要拆"这个判断既不稳定也不准确——重构后行数上升，会被误读成变更差。

## 决策

1. 新增 `scripts/check-complexity.mjs`，用 TypeScript AST 计算四项指标：文件行数、最长函数行数、最大圈复杂度（分支 + `&&`/`||`/`??`）、导出数。
2. 阈值：文件 400 行、函数 60 行、圈复杂度 15、导出 12。测试文件与 `tests/` 目录不参与函数级统计（`describe` 天生是长函数，纳入只会制造噪声）。
3. **基线只降不升**：`plan/complexity-baseline.json` 只登记当前已超标的文件及其实测值；新文件超标即失败，老文件只允许改善，取值恶化即失败。达标文件自动移出基线。
4. 行数只作参考，不再作为拆分依据；`--report` 模式给出最长函数排行，供拆分排期。
5. 门禁接入 `check:quality`，与 lint / typecheck / boundaries / coverage 同级。

## 后果

- "该拆哪里"变成可复现的排序（最长函数 + 圈复杂度），而不是看行数猜。
- 基线是一份显式的技术债清单：181 个文件（当前实测），允许存在但只能变好。
- 代价：需要维护基线 JSON；基线膨胀会被视为债务恶化，需在评审中解释。

## 回滚

删除脚本、基线与 `check:quality` 中的一行即可；不影响任何运行时代码。

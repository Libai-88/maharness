# 安全、权限与信任模型

关联登记项：SEC-01、SEC-02、SEC-03、SEC-04、SEC-05、SEC-06、SEC-07。

## 现状证据

历史审查中的 PowerShell、敏感路径、SSRF、MCP、密钥和 HTTP 控制面缺陷已在 Batch 1-5 完成并有回归用例。当前 README 已明确：插件完全信任、没有多用户/多租户模型、默认只适合本机使用；下一阶段重点是把这些边界变成可配置、可审计、可验证的信任模型。

威胁模型 v1 已按当前单机部署建立，映射 HTTP/UI、审批、文件、PowerShell、MCP、Provider/HTTP、插件、凭据及 Trace 数据入口，并列出现有测试和剩余风险，见 [threat-model-v1.md](threat-model-v1.md)。

变更类 API 的 token guard 在每个请求读取 `MAHARNESS_API_TOKEN`，支持运行期间轮换；审批凭据具备过期与一次性消费校验。共享 `server/security-policy.ts` 提供 API token 与审批响应共用的凭据决策，并为来源校验、凭据授权及 `/api/events` SSE 生命周期发布脱敏审计事件。事件仅记录主体类别、能力、路由模板与拒绝原因，不记录凭据或请求参数；记录持久化于 SQLite，最多保留 10,000 条，并可通过 `GET /api/security/audit` 查询最近记录。API token guard 按来源地址使用进程内失败锁定：默认 60 秒窗口内连续 5 次错误凭据后锁定 60 秒，正确凭据清除计数，缺失凭据只拒绝并审计而不消耗错误凭据额度；锁定返回 429 与 `Retry-After`。限制器按 guard 实例隔离，最多保留 1024 个来源，服务重启后状态清空。

供应链审计按 [supply-chain-policy-v1.md](supply-chain-policy-v1.md) 执行：npm 依赖以双仓锁文件精确锚定并以 `npm ci` 为唯一安装方式；技能包以锁文件哈希 + 逐文件清单校验后原子换入；插件以内容聚合哈希快照 + manifest 兼容范围 + capabilities 白名单加载；升级与回滚路径按该文档操作（SEC-07）。

## 目标

默认拒绝高风险行为，审批不可绕过，敏感数据不可由 Agent 工具读取或写入；插件权限、网络、进程和文件边界明确。

## 执行

1. 把现有 API token、来源校验、敏感路径和 SSRF 防护整理成版本化安全策略，并增加启动自检和配置诊断。
2. 将 HTTP 审批、workspace、rules 和 provider 管理接入统一权限审计，覆盖 token 轮换、失败锁定和 SSE 生命周期。
3. 引入插件 manifest 权限声明、签名/哈希、隔离等级和高风险能力审批；保留完全信任模式作为明确的本地开发模式。服务端第三方插件执行不得把 Node `vm` 当安全边界，隔离需依赖独立 OS 进程身份/ACL 或容器。
4. 建立威胁模型、攻击回放集和安全事件审计，持续验证已修复边界不回退。

## 范围

`kernel/sandbox.ts`、`core/powershell`、`core/search`、`core/mcp`、`server/secrets.ts`、`server/routes`、`kernel/plugin-loader.ts`。

## 依赖、迁移和风险

依赖 04 的攻击回放和 10 的身份/部署模式。权限 manifest 增加版本字段，未声明权限的旧插件只允许在本机 trusted 模式运行；不自动授予远程模式权限。迁移需逐插件生成权限清单并让用户确认。误拒绝会影响插件兼容性，以 dry-run 审计报告和逐插件回滚开关控制。跨 OS 进程边界的插件隔离属于上线阻断项；若 Windows ACL、受限令牌和 Job Object 不能提供经验证的边界，则团队模式须使用容器/虚拟机执行器。

## 验收

历史 A/B 安全回归全绿；策略配置错误时启动自检失败而不是静默降级；未授权 HTTP 请求全部拒绝；恶意插件在声明权限外加载失败或进入隔离模式。

## 回滚

新增策略用配置版本控制；数据库密钥/权限迁移先备份；发现误拦时只回退对应策略开关，不回退审计和拒绝日志。量化目标：未授权操作拒绝率 100%；合法本地工作流误拒绝率 < 1%；安全事件可在 1 分钟内从 Trace 定位到主体、能力和对象。团队模式完成独立红队/攻击回放，不能依赖 UI 或提示词作为授权边界。

## 测试与指标

- 单测覆盖策略解析、权限合并、凭据轮换、审计字段和模式启动检查。
- 集成/红队测试覆盖 DNS rebinding、重定向、越权插件、MCP 子进程、跨租户访问和隔离逃逸。
- 指标：未授权拒绝率 100%，安全回放通过率 100%，合法本地误拒绝率 < 1%，高风险事件定位 P95 < 1 分钟。

插件 manifest 可通过 `permissions.capabilities` 声明允许登记的 capability/name；`ctx.register` 拒绝未声明登记、发出 `plugin.permission.denied`，并在加载失败时回收插件已登记效应。未声明 `permissions` 的既有插件仍按本机 trusted 兼容模式加载。确定性回放新增 capability escalation 攻击，当前安全攻击阻断为 4/4。该白名单只约束 `ctx.register` 能力登记；插件仍在宿主进程执行并可访问 `ctx.kernel`，因此不构成完整权限沙箱或进程隔离。SEC-04 与 SEC-06 继续保持开放。

## 完成定义

SEC-01 至 SEC-07 均完成代码、攻击回放、威胁模型、文档事实检查和可验证回滚；任何隔离逃逸均阻断 remote/team 发布。威胁模型 v1 已完成初版；CI 现校验引用路径存在及 `test:security` 测试映射。SEC-01 仍进行中：仍需将全部暴露入口纳入周期性版本复核，并为控制有效性补齐集成级验证。
